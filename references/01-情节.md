# 阶段 1 · 故事情节方向

歌词之前先定情节。因为歌词是从情节里长出来的，反过来做会得到一首空泛的歌配一个硬凑的故事。

## 产出三个情节方向，让用户三选一

三个方向必须是**对同一个素材的三种不同解法**，不是三个不同的故事。差别要落在这三件事上：

- **视角不同** —— 谁在讲？等待的人／被等的人／旁观的第三者／一个物件
- **时间结构不同** —— 顺叙／倒叙（从结局开始）／回环（结尾回到开头那一格）
- **收尾不同** —— 释然／更深的失落／什么都没变／反转

### 输出到 `1-情节/三个方向.md`

```markdown
# 三个情节方向

**创作描述（用户原文或提炼表）**：<原文>

---

## 方向 A · <名字（4-8 字，有画面的名字）>

- **一句话故事**：<主角做了什么，结果怎样>
- **视角**：<谁在讲>
- **情绪弧线**：<如 期待→焦灼→崩塌→释然>
- **核心物件**：<一件具体的东西>
- **最终定格画面**：<最后一帧是什么>

**四段怎么走**
1. <第1段做什么事>
2. <第2段做什么事>
3. <第3段做什么事>
4. <第4段做什么事>

**这个方向的特点**：<一句话，说清它和另外两个差在哪、适合什么调性>

---

## 方向 B · ...
## 方向 C · ...

---

> 三个方向的差别：A 是<X>视角，B 是<Y>视角，C 是<Z>视角。
> 如果你想要<某种效果>，选 A；想要<另一种>，选 C。
```

最后那段对比很重要——**不要只是把三个方案摆出来让用户自己比**，要直接告诉他「想要什么效果就选哪个」。

## 三个方向的质量要求

- 每段必须是一个**具体事件**，不是一种情绪状态。「她很难过」不是事件，「她把多买的伞立在空凳上」是事件
- 每个方向都要有一件**可被手拿、可被破坏、有状态变化**的核心物件。这件东西会在阶段 6 变成道具
- 情绪弧线必须有**四个不同的阶段**，不能是「难过→更难过→还是难过→特别难过」
- 最终定格画面要具体到能画出来，不要写「她释然了」
- 三个方向不许有两个收尾相同

## 用户选定后 → `1-情节/定稿.md`

把选中的方向展开，补上歌词阶段和分镜阶段需要的东西：

```markdown
# <情节名>

- **一句话故事**：
- **视角**：
- **情绪弧线**：
- **核心物件**：<这件东西会在阶段 6 变成道具>
- **最终定格画面**：

## 分段骨架

| 段 | 事件（想做什么→阻碍→行动→结果） | 情绪 | 物件状态 |
|---|---|---|---|
| 第1段 | | | |
| 第2段 | | | |
| 第3段 | | | |
| 第4段 | | | |

## 这首歌真正讲的是什么

<一句话。不是情节概括，是主题。例如：不是「他没来」，是「我早就知道他不会来，但还是买了第二把伞」>

## 要避免的俗套

- <3-5 条，根据题材列。写具体的镜头，不要写「不要太俗」>
```

最后那两段是后面所有阶段的北极星：

- **「真正讲的是什么」** 决定歌词的立意和最终定格画面
- **「要避免的俗套」** 会被原文抄进画风锁的禁止清单

## 用户已经有情节时

用户贴了完整故事、或者明确说「就按我说的来」，不要硬给三个方向。直接整理成 `定稿.md`，但仍然要做两件事：

1. **补齐分段骨架** —— 把他的故事切成 N 段，每段一个具体事件，给他确认分段对不对
2. **问收尾** —— 很多人讲故事会漏掉结尾。「这个故事最后一帧你想停在哪？」

## 用户想混搭时

「A 的情节配 C 的结尾」这种很常见，直接做，不要让他二选一。混搭后把定稿给他确认一次。

更新 `进度.json` 的 `情节` 和 `stage: 2`。
