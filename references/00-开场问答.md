# 阶段 0 · 立项问答

这是整个 skill 最该下功夫的地方。**没问清楚就开工，后面每个阶段都在给错误的前提打工。**

## 引导的四条原则

1. **一次只问一批。** 一批 2-4 个问题，不要一口气抛十个。
2. **每个问题都给推荐值。** 用「推荐：XXX」标出来，并用一句话说明为什么推荐它。用户能直接说「都按推荐来」就走完。
3. **能从素材里读出来的，就不要问。** 用户贴了一大段故事，里面已经写了人物、场景、情绪的，直接提炼出来让他确认，而不是重新问一遍。
4. **最后一定要核对。** 开工前把所有参数汇总成一张确认单，让用户过目。这一步不许省。

## 第 0 步：识别用户给的是什么

用户的输入大致分三类，处理方式完全不同：

| 用户给的 | 判断依据 | 怎么处理 |
|---|---|---|
| **一大段内容** | 贴了几百字以上的故事、小说片段、日记、歌词、文案、剧本 | 走下面的「素材提炼」，先提炼再确认，**不要直接问参数** |
| **一句话或几个词** | 「雨天便利店等人」「赛博朋克女战士」「想做个燃一点的」 | 直接进「第 1 批问题」 |
| **一个现成需求** | 已经说清楚了歌名、时长、画风、段数 | 跳过提问，直接出确认单让他核对 |

## 素材提炼（用户贴了长内容时）

**先读，再提炼，再确认，最后才问参数。**

提炼成这张表，发给用户确认：

```markdown
我从你给的内容里读到这些，你看对不对：

| 维度 | 我读到的 |
|---|---|
| 核心情绪 | <一句话。这是最重要的一行> |
| 主要人物 | <几个人，各自什么身份/状态> |
| 关键场景 | <2-3 个具体空间> |
| 关键物件 | <反复出现或有象征意味的东西> |
| 情绪转折 | <从什么状态到什么状态> |
| 最有画面感的一句/一段 | <原文摘一句，这往往就是 MV 的定格画面> |

要改哪里直接说，或者说「对」我就往下走。
```

提炼的要点：

- **抓「变化」不抓「描述」。** 原文里人物从 A 状态变成 B 状态的那个转折，比外貌描写重要得多
- **抓具体物件。** 一封信、一把伞、一只碗比「孤独」「思念」有用一万倍，因为它能被画出来
- **抓原文最有画面感的一句。** 它通常就是全片的最终定格画面
- 原文很长时，不要逐段复述。提炼表就是交付物，不要再附一份摘要

## 第 1 批问题 · 基本参数

一次问完这四个，每个都带推荐值：

```
在开始之前，几个基本设定（括号里是我的推荐，直接说「都按推荐来」也行）：

1. 时长？
   · 30 秒 —— 2 段，适合发短视频平台
   · 60 秒（推荐）—— 4 段，够讲一个完整的起承转合，也是 AI 出歌最稳的长度
   · 90 秒 —— 6 段，能有副歌重复，但 AI 出歌容易跑偏

2. 歌词长度？
   · 跟时长绑定（推荐）—— 60 秒就是 5-6 行，这是控制 AI 出歌时长最有效的办法
   · 我自己有歌词 —— 你贴给我，我按你的来分段

3. 语言和人声？
   · 中文女声（推荐，视题材而定）／中文男声／英文／无人声纯器乐

4. 每段多少秒、几宫格？
   · 15 秒 / 12 宫格（推荐）—— 节奏密，适合卡点和快剪
   · 15 秒 / 9 宫格 —— 节奏松，单格信息足，适合叙事
```

### 时长 → 段数 对照（推导用，不用问用户）

| 总时长 | 段数 | 每段 | 歌词行数 |
|---|---|---|---|
| 30 秒 | 2 段 | 15 秒 | 3-4 行 |
| 60 秒 | 4 段 | 15 秒 | 5-6 行 |
| 90 秒 | 6 段 | 15 秒 | 7-8 行 |

**歌词越短，歌越短。** 这是控制时长唯一可靠的手段，不要靠在提示词里写「60 秒」。

## 第 2 批问题 · 怎么交付

```
5. 你是手动在画布上出图，还是已经接好了生图模型？
   · 手动（推荐，大多数人是这样）—— 我产出可以直接复制粘贴的提示词包
   · 自动 —— 我直接调模型出图，你只要确认

6. 用哪个画布/模型？（影响参考图的写法）
   · 不确定（推荐）—— 我用通用写法，哪个都能用
   · Gemini / nano banana ／ 即梦 ／ 可灵 ／ Midjourney ／ 其他
```

## 第 3 批问题 · 画风（放在情节定了之后问）

**画风不要一上来就问。** 等故事情节选定了再问，因为那时候你才能给出有依据的推荐。

```
7. 画风？（根据你的故事，我推荐 XXX，因为 YYY）
   列 3 个最适配的，而不是把 8 种都摆出来让他挑花眼
```

### 题材/情绪 → 画风推荐对照

拿这张表推导推荐值，并且**必须说出推荐理由**：

| 故事的调性 | 首选 | 备选 | 理由模板 |
|---|---|---|---|
| 都市日常、细腻情感、青春 | 精致写实动漫 | 水彩插画 | 五官细腻能承载微表情，适合靠眼神讲故事 |
| 未来、科技、异化、夜城 | 赛博朋克 | 3D 渲染 | 霓虹与暗部对比强，能把疏离感做进光里 |
| 回忆、温柔、淡淡的遗憾 | 水彩插画 | 精致写实动漫 | 边缘渗透天然有「记不清了」的质感 |
| 古风、禅意、江湖、山水 | 国风水墨 | 水彩插画 | 留白本身就是情绪，不用画满 |
| 热血、对抗、英雄、爆发 | 欧美漫画 | 3D 渲染 | 粗线条和强明暗能撑住大动作 |
| 治愈、童话、家庭、动物 | 皮克斯动画 | 3D 渲染 | 表情夸张但可信，暖光讨喜 |
| 质感、时尚、人物特写 | 真人写实 | 3D 渲染 | 皮肤纹理和自然光是这类片子的全部 |
| 梦境、意识流、抽象 | 水彩插画 | 国风水墨 | 不需要清晰边界，正好 |

镜头风格和 MV 概念方向也一并给推荐，别让用户选三次：

| 故事类型 | 镜头风格 | 概念方向 |
|---|---|---|
| 有明确事件和因果 | 剧情叙事 | A 剧情叙事 MV |
| 情绪为主、没有完整剧情 | 情绪抽象 | B 情绪意象 MV |
| 歌手/舞者是主角 | 舞蹈卡点 或 音乐现场 | C 表演舞台 MV |
| 要的就是好看 | 时尚大片 | B 情绪意象 MV |

## 参数确认单（开工前必须给，不许省）

所有问题答完，汇总成这张单子让用户过目：

```markdown
## 开工前核对一下

| 项目 | 定下来的 |
|---|---|
| 创作描述 | <用户原文，或提炼表的核心情绪> |
| 歌名 | <待定，歌词阶段确定> |
| 总时长 | 60 秒 |
| 分段 | 4 段 × 15 秒 |
| 歌词 | 中文女声，5-6 行（[Verse]2-3 + [Chorus]3） |
| 画风 | 精致写实动漫 |
| 镜头风格 | 剧情叙事 |
| 概念方向 | A 剧情叙事 MV |
| 宫格 | 12 格 |
| 人物 | 1 位主角 |
| 场景 | 2 个核心场景 |
| 道具 | 1 件核心道具 |
| 模式 | 手动复制粘贴 |
| 画布 | 通用写法 |
| 项目位置 | ./mv-<项目名>/ |

没问题我就开始建项目、出故事情节方向了。要改哪项直接说。
```

用户确认后，才跑 `新建项目.py`，才进阶段 1。

## 快速通道

用户说「都按推荐来」「你定吧」「随便」「快点」这类话时：

- 不要再逐批问，直接按推荐值填满整张确认单
- 确认单还是要给，但告诉他「以下全部按推荐值填好了，你扫一眼，没问题我就开工」
- 情节和画风这两个仍然要让他选，因为这是创作主张，不是技术参数。但可以合并成一次问

## 什么时候该追问

用户的描述里缺了这些，追问一句：

- **没有任何具体物件** —— 「有没有什么反复出现的东西？一封信、一把伞、一只手表都行。有件具体的东西，分镜会好画很多」
- **没有情绪转折** —— 「这个故事最后是往哪个方向收？释然、更难过，还是什么都没变？」
- **人物关系不明** —— 「是一个人的独角戏，还是两个人之间的事？」
- **只有形容词没有场景** —— 「这件事发生在什么地方？一个具体的空间就够」

追问最多一轮。用户懒得答就自己推导，并在确认单里标出「<这项是我推导的>」。
